# Historical Change Log Index (English)

## Current configuration notes — 2026-11-02

- Optional OptiScaler support now includes `scripts/optiscaler_manager.py` and `docs/OPTISCALER-MANAGER.md`: stable-only checks, SHA-256-verified downloads, explicit per-game installation, status, rollback, and removal. It is not a NixOS/Home Manager package or background service and leaves LSFG-VK and latency-layer defaults unchanged.
- `CHANGELOG.md` is the maintained current change summary; its 2026-10-28 entry covers installer and VM diagnostic hardening, VFIO handoff, LSFG-VK profiles, registered-libvirt XML preservation, embedded-script extraction boundaries, and CI audit follow-ups.
- The 602-line duplicate block in `scripts/test-installer-invariants.sh` has been removed. `CONTRIBUTING.md` has one valid validation block; the extractor now refuses to cross Nix attribute boundaries or accept unterminated embedded strings, with a focused regression test.
- Sixth audit follow-up (2026-10-30): README now documents the Hyprland Lua minimum, RX 6700 XT ROCm override, host-memory recommendation, e1000e NIC and USB preflight; the WuWa geometry parser accepts monitor modes without a refresh-rate suffix. The sixth supplied ZIP measurements are recorded as unverified provenance, not as a canonical release.
- Seventh audit follow-up (2026-10-30): main/de33e2d was rechecked; the 62-blob Git tree was confirmed; the supplied ZIP's measurements were recorded as unverified; inventory arithmetic inconsistencies were flagged; README VM-sync wording and the Hyprland 0.55+ evaluation guard were corrected. The VM XML template was left untouched.
- 2026-10-29: LSFG-VK v2 is now the active target. Home Manager emits `version = 2` with `[[profile]]` entries, the flake builds the pinned `.#lsfg-vk-v2` package, and CI validates the v2 schema/package. The installer backup and rollback transaction includes `nixos/lsfg-vk-v2.nix`.
- Cross-conversation recheck added fail-closed VFIO service-stop verification plus mocked stop/restore failure tests. Installer `stateVersion` source discovery now detects conflicting, duplicate, or non-literal definitions instead of silently selecting one; the tests exercise these paths. `INSTALLATION.md` now invokes VM XML sync with `--domain win10`, and both manual and automated migration docs describe the persistent registered libvirt XML source.
- CI builds the canonical source ZIP with `scripts/package-source-zip.sh`, verifies tracked-file completeness and executable bits, ensures `.git/` is excluded, and publishes a world-readable artifact. Prefer the validated CI artifact or run the packaging helper rather than creating an arbitrary ZIP export.
- Release-note ranges are event-specific: a pushed version tag uses git-cliff `--current` because HEAD is that tag; a manual dispatch from `main` uses `--latest` because the new release tag does not exist yet. The workflow's documentation-integrity regression checks this distinction.
- Source provenance is pinned consistently across clean install, manual migration, and `install.sh`; VM preparation requires a matching, clean checkout and fails closed when the revision marker is absent or incorrect. Canonical ZIPs embed the packaged commit and validate it before publication. Rollback now backs up and restores the marker.
- Home Snapper checks the live `/home` mount, the `@home` subvolume, target device UUIDs, and any active `/home/.snapshots` mount; the final selected hardware configuration is checked again before hook deployment.
- Installer profile backups, Home Manager `home.stateVersion` fallback, and `~/` wallpaper paths are pinned to `/home/localhost` even when the script is invoked from a different administrator home.
- The VFIO hook rechecks services recorded inactive just before handoff and stops/verifies a service that became active in the meantime; mocked regression coverage exercises this race. This remains distinct from physical GPU lifecycle validation.
- The active kernel package is `linuxPackages-cachyos-rt-bore-lto` from the CachyOS upstream `master` input. The kernel version is not hard-coded in `nixos/flake.nix`; `nixos/flake.lock` records the resolved revision (`02ba4db52e62e1fbece80402d369127ae77cbbeb`) for reproducibility. To advance the CachyOS input, use `sudo nix flake update --flake /etc/nixos/nixos cachyos-kernel`, inspect the lock diff, and validate the resulting build. The RT-Bore-LTO ThinLTO package is not published in the upstream binary cache, so a local build is expected. The project owner reports that the target machine successfully rebuilt and compiled this kernel, started and shut down the Windows VM normally, and returned to the Hyprland host session.
- The system enables the low-latency Vulkan layer globally with `LOW_LATENCY_LAYER=1` but leaves `LOW_LATENCY_LAYER_REFLEX` unset by default, preserving the AMD Anti-Lag interface. Compatible games can opt into Reflex with `LOW_LATENCY_LAYER_REFLEX=1 %command%`; incompatible games can opt out of the layer with `DISABLE_LOW_LATENCY_LAYER=1 %command%`. The upstream `low_latency_layer` v0.2.0 release also documents an incompatibility with `obs_vkcapture`.
- The installer checks `/etc/nixos/hashedPassword` as the local `localhost` account password hash (presence, non-empty content, `root:root` ownership, mode `0600`). It warns if invalid so the manual step can repair it before activation. This file does not enable SSH password authentication.
- `install.sh` updates the QEMU hook source under `/etc/nixos/nixos/hooks/qemu`; the active NixOS-generated libvirt hook is refreshed only after a successful `nixos-rebuild switch`. VM XML synchronization is conditional: when `win10` is registered, the installer prefers a validated `virsh dumpxml --inactive win10` export; otherwise it updates `/var/lib/libvirt/win10.xml` only if that deployed XML already exists. Libvirt query/export failures stop before writes, and existing registered/on-disk definitions are backed up. If neither a registered domain nor a deployed XML exists, `install.sh` writes no VM XML and defers fresh XML generation to the post-install VM-preparation flow. It never runs `virsh define` automatically.
- Installer backups are retained and are not pruned automatically. Fail2ban permits loopback without banning but private LAN ranges remain subject to the ban policy. SSH listens on TCP 22; password and keyboard-interactive authentication are disabled, and public-key authentication is required. `AllowUsers = [ "localhost" ]` restricts the permitted account name, not the remote source IP or listening interface. Root login remains disabled, so restrict port 22 at the network edge and do not expose it to untrusted networks.
