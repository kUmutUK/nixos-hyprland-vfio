# Historical Change Log Index (English)

This legacy filename now contains an English current-state summary so older links remain useful. The maintained and current change log is [`CHANGELOG.md`](CHANGELOG.md).

## Current configuration notes — 2026-10-27

- `CHANGELOG.md` is the maintained current change summary; its 2026-10-27 entry covers installer and VM diagnostic hardening, VFIO handoff, LSFG-VK profiles, registered-libvirt XML preservation, embedded-script extraction boundaries, and CI audit follow-ups.
- The 602-line duplicate block in `scripts/test-installer-invariants.sh` has been removed. `CONTRIBUTING.md` has one valid validation block; the extractor now refuses to cross Nix attribute boundaries or accept unterminated embedded strings, with a focused regression test.
- Cross-conversation recheck added fail-closed VFIO service-stop verification plus mocked stop/restore failure tests. Installer `stateVersion` source discovery now detects conflicting, duplicate, or non-literal definitions instead of silently selecting one; the tests exercise these paths. `INSTALLATION.md` now invokes VM XML sync with `--domain win10`, and both manual and automated migration docs describe the persistent registered libvirt XML source.
- CI builds the canonical source ZIP with `git archive`, verifies `install.sh` retains Unix executable mode, and ensures `.git/` is excluded. Prefer the validated CI artifact or use the documented `git archive` command rather than an arbitrary ZIP export.
- The active kernel package is `linuxPackages-cachyos-rt-bore-lto` from the CachyOS upstream `master` input. The kernel version is not hard-coded in `nixos/flake.nix`; `nixos/flake.lock` records the resolved revision (`02ba4db52e62e1fbece80402d369127ae77cbbeb`) for reproducibility. To advance the CachyOS input, use `sudo nix flake update --flake /etc/nixos/nixos cachyos-kernel`, inspect the lock diff, and validate the resulting build. The RT-Bore-LTO ThinLTO package is not published in the upstream binary cache, so a local build is expected. The project owner reports that the target machine successfully rebuilt and compiled this kernel, started and shut down the Windows VM normally, and returned to the Hyprland host session.
- The system uses `LOW_LATENCY_LAYER=1` and `LOW_LATENCY_LAYER_REFLEX=1` by default. Incompatible games can opt out with `DISABLE_LOW_LATENCY_LAYER=1 %command%`. The upstream `low_latency_layer` v0.2.0 release also documents an incompatibility with `obs_vkcapture`.
- The installer checks `/etc/nixos/hashedPassword` presence, non-empty content, `root:root` ownership, and mode `0600`; if invalid, it warns so the documented manual step can repair the file before activation.
- `install.sh` updates the QEMU hook source under `/etc/nixos/nixos/hooks/qemu`. The active NixOS-generated libvirt hook is refreshed only after a successful `nixos-rebuild switch`. The installer writes the VM XML but does not automatically run `virsh define`. When `win10` is registered, VM XML synchronization prefers a validated `virsh dumpxml --inactive win10` export; libvirt query/export failures stop before writes, and both registered persistent and existing on-disk XML are backed up. If the domain is not registered, an existing deployed XML remains the source of truth; only its two GPU/audio PCI source addresses are synchronized.
- Installer backups are retained and are not pruned automatically. Fail2ban permits loopback without banning but private LAN ranges remain subject to the ban policy. SSH is enabled on TCP 22; `AllowUsers = [ "localhost" ]` restricts the permitted account name, not the remote source IP or listening interface. Root login remains disabled, so restrict port 22 at the network edge and do not expose it to untrusted networks.
- The historical note under release `[1.3.6]` about `amd_iommu=on` is not the current state. The active configuration does not add `amd_iommu=on` or `iommu=pt`; enable IOMMU/AMD-Vi in firmware and verify it at runtime.
