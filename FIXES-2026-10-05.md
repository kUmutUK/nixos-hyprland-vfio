## Kanıtlar

### 1 — `{H:M}` / `{user}` → `$TIME` / `$USER`

`hyprlock v0.9.6 · src/renderer/widgets/IWidget.cpp · IWidget::formatString()` — desteklenen
ikame tam olarak şunlar:

```
$DESC  $USER  $TIME  $TIME12  $ATTEMPTS  $LAYOUT  $FAIL
$PAMFAIL  $PAMPROMPT  $FPRINTFAIL  $FPRINTPROMPT  <br/>  cmd[…]
```

`{` hiç geçmiyor, pango işaretlemesi de `<b>`/`<i>` kullanıyor. Yani ekranda **tam olarak**
`{H:M}` ve `{user}` yazıyordu. Nerd Font saat/kullanıcı glifleri (U+F017 / U+F007) korundu.

### 2 — Yinelenen label

`hyprlockConf` içinde 8 `label` bloğu vardı; ikisi byte-byte aynıydı ve aynı
`position = 0, -260` konumundaydı (v3 düzeltmesi `button` bloklarının ikisini birden
düzeltirken yorumu da kopyalamış). Artık 7 label, yinelenen yok.

### 3 — `exec-once`

Hyprland `exec`/`exec-once`'i fork edip **beklemez**; iki ayrı satır paralel çalışırdı.
`import-environment` bitmeden başlayan `mpvpaper-watchdog`, `$HYPR_SOCK`'u bulamayıp
`exit 1` veriyordu (`Restart=on-failure` 3 sn'de iyileştiriyordu ama her login'de bir
failed unit). Artık tek satır, `;` ile zincirlenmiş.

### 4 — impermanence / home-manager `follows`

`flake.lock`'ta iki HM rev'i vardı: kök `7b4c5ec4beda` (nixpkgs `7a0f122`) ve impermanence'ın
getirdiği `home-manager_2 c47b2cc64a62`. `impermanence.inputs.home-manager.follows`
tanımlı değildi, yani `home.persistence`'u değerlendiren HM ile onu tanımlayan modülün
yazıldığı HM farklıydı. Eklenen satır ikisini tek rev'e bağlar.

> Not: `nix flake lock --update-input impermanence` (veya `nix flake update`) çalıştırıp
> `home-manager_2` node'unun düştüğünü doğrulayın.

### 5 — swtpm

`qemu.runAsRoot = false` + `qemu.swtpm.enable = true` + `win10.xml`'de `<tpm model="tpm-crb">`
var; ama sahiplik servisi yalnızca `images` ve `qemu` dizinlerini chown ediyordu.
`/var/lib/libvirt/swtpm` eklendi.

### 6 — OVMF NVRAM şablonu

`<loader>` 64-bit `edk2-x86_64-code.fd` kullanırken `<nvram template=…>` **i386** (IA32)
build'ini gösteriyordu. x86_64 misafir için `edk2-x86_64-vars.fd` doğru eşlemedir; her iki
dosya da `/run/libvirt/nix-ovmf` altında mevcut (nixpkgs `libvirtd-config` qemu'nun
firmware JSON'larındaki tüm `nvram-template` adlarını kopyalar), yani değişiklik
başlatma davranışını bozmaz — sadece doğru şablonu kullanır.

### 7 — `hyprlandMonitorLine`

Boş monitör adı Hyprland'da *"kuralı tüm çıkışlara uygula"* demektir. `install.sh` artık
topladığı `monitor_output` (örn. `DP-3`) değerini `hyprlandMonitorLine` satırına gömer;
kullanıcıya gösterilen örnek de artık boş ad içermiyor.

### 8 — hyprlock `cmd[]` PATH

`/run/current-system/sw/bin` yalnızca `environment.systemPackages`'ta **açıkça yazılmış**
paketlerin ikililerini içerir; `awk` yazılı değildi. CHANGELOG 1.2.0'da aynı sorun
`mpvpaper-watchdog` için `pkgs.gawk` eklenerek çözülmüştü, hyprlock label'larına
uygulanmamıştı. Artık `wpctl`, `awk`, `nmcli`, `date` mutlak store yolundan çağrılıyor.

### 10-12 — Dokümantasyon

`onMouseEvent` referansı 0.55.0'den kalma `438-448` idi; v0.56.2'de **477-488**
(`"mouse:" + std::to_string(e.button)` `:488`'de). `hyprland.conf:342` → binding `:351`'de.
`security.pam.services.hyprlock` satırının **kendisi doğru** (kanonik NixOS reçetesi),
yalnızca gerekçesi düzeltildi: dosyayı `security.pam` modülü üretir, hyprlock'un systemd
servisi değil; bu config'te `programs.hyprlock` enable edilmediği için
`systemd.services.hyprlock` diye bir şey yok; varsayılan stack pam alt modülünün
`useDefaultRules=true` + `unixAuth=true` varsayılanlarından gelir.

## `hyprland.lua` iddiası hakkında (sorgulandı, doğrulandı)

Sorgulaman haklıydı — kanıtı çıkardım:

```
$ curl -s https://api.github.com/repos/hyprwm/Hyprland/git/refs/tags/v0.56.2
 tag obj: efb50993780079460b0cbed1363e2166a2de1d9f | type: commit

$ ls src/config/supplementary/  (v0.56.2)
   dir executor
   dir jeremy
   dir propRefresher

$ curl -s .../v0.56.2/src/config/supplementary/jeremy/Jeremy.cpp | head -3
#include "Jeremy.hpp"
#include "../../../Compositor.hpp"
  satır: 54   sha256: 766a73d3d820e86a...
```

`Jeremy.cpp` gerçek bir dosya, `v0.56.2` gerçek bir tag. İçindeki `getMainConfigPath()`:

```cpp
const auto LUA_PATHS  = Hyprutils::Path::findConfig("hyprland", "lua");
const auto CONF_PATHS = Hyprutils::Path::findConfig("hyprland", "conf");
if      (LUA_PATHS.first.has_value())  return ...lua...;   // ÖNCE LUA
else if (CONF_PATHS.first.has_value())  return ...conf...;
else if (LUA_PATHS.second.has_value())  return ...lua...;  // XDG_CONFIG_DIRS
```

ve `src/config/ConfigManager.cpp`:
```cpp
if (filePath.extension() == ".lua") g_mgr = makeUnique<Lua::CConfigManager>();
else { filePath.replace_extension(".conf"); g_mgr = makeUnique<Legacy::CConfigManager>(); }
```

Halâ `src/config/legacy/` altında tam bir v1 ayrıştırıcı var ve 0.56.2'de `hyprland.conf`
**şu an** çalışıyor — ama **yalnızca** PATH'te hiçbir yerde `hyprland.lua` bulunmadığı için.
`legacy/DefaultConfig.hpp` içindeki örnek config 10 satırlık bir STUB ve kendisi
"Use the default lua config" diyor, üstelik yeni `bind` sözdizimiyle yazılmış.

Bu yüzden bulgu "şu an bozuk" değil, **"tek bir dosya yolundan sessizce devre dışı kalabilir"**.
README'ye uyarı kutusu olarak eklendi. Kısa doğrulama:

```bash
ls ~/.config/hypr/hyprland.lua 2>/dev/null && echo "⚠️ Lua config var — .conf yok sayılıyor!"
hyprctl configversion
```

## Kapsam dışı bırakılanlar

- `install.sh`'in clone'u yerinde değiştirip `git update-index --skip-worktree`
  uygulaması — davranışsal, kurulum akışını değiştirir; ayrı karar gerekir.
- `impermanence`'i tamamen kaldırmak (`home.file` + tmpfiles'e geçiş).
- `power-profiles-daemon` ↔ `ananicy` ↔ `gamemode` üçlüsü.
- Üç Vulkan implicit layer'ı (`lsfg-vk` + `low_latency_layer` + `vkbasalt`).
- `waypaper` ↔ `mpvpaper` çakışması.
- Filename'deki Türkçe `İ` (`F-İX-MAN-İFEST.md`) — silinmesi/yeniden adlandırılması
  gerekiyor ama bu bir teslim kararı. **Not:** bu dosya adı ASCII "I" değil, U+0130
  (`İ`) içeriyor; `FIX-MANIFEST.md` diye yazılan her referans eşleşmez.
- `low-latency-layer` `sha256`'ının test edilmesi — sandbox'ta `nix` yok, çalıştırılamadı.
  İlk `nixos-rebuild`'den önce `nix build` ile doğrulanmalı.
